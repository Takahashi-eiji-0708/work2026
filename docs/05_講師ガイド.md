# 講師ガイド

## 1. この研修の運営方針

- **受講者は3名程度**。講義で全員に話すより、**横について画面を見ながら支援する時間** を多く取る
- 講義は短く、**「やってみる → 気付く → 説明する」** の順で進める（先に説明しすぎない）
- 受講者の出力は毎回違う。**違いそのものを教材にする**（「Aさんと Bさんで結果が違うのはなぜ？」）
- セキュリティは第3章だけで終わらせず、**すべての演習でセキュリティチェックを声に出して確認する**
- 研修全体を「みなと精機への提案活動」というストーリーでつなぐ。章の冒頭で **「今どの段階か」** を必ず伝える

## 2. 事前準備

`06_環境準備チェックリスト.md` の「講師による機能確認」を3営業日前までに実施します。
**Copilot の画面・機能名が変わっていたら、テキストとの違いを当日の冒頭で伝えます。**

## 3. 時間帯ごとの進め方

### Day1 9:30–9:50 オリエンテーション（20分）

- 研修のゴール：「安全に」「成果物まで」「自分の業務で」
- ストーリーの説明：ELIソリューションズの営業として、みなと精機に提案する。Day2 の昼には提案書・見積・スライドの一式が手元に残る
- 自己紹介：「名前・担当業務・生成AIの利用経験・この研修で持ち帰りたいもの」
- **環境確認**：全員の画面で Copilot のサインイン状態、OneDrive の自動保存を確認（ここでつまずく人が多い）
- 第10章のトラック希望（開発／企画）をこの時点で聞いておく

### 第10章 営業業務への応用ワークショップ（100分）

- 最初の30分（STEP1〜3）は全員一緒に進める
- 15:10 から開発トラックの受講者は Codex に移る。**開発トラックの受講者の最初の10分（ステージ0）は講師がそばにつく**
- 企画トラックの受講者には、**「業務の中身は Copilot に入れない。一般化して相談する」** を繰り返し伝える
- 開発トラックが遅れても、**ステージ2（議事録生成のモック）まで動けば成功** とする。残りは持ち帰り
- 開発トラックが誰もいない回は、講師が15分程度、ステージ0〜2を実演して見せる

**開発トラックでよくあるつまずき**

| 症状 | 対応 |
|---|---|
| Codex が起動しない・サインインできない | 講師画面の実演に切り替え、本人は企画トラックへ |
| Codex が大量のファイルを一度に作ってしまう | 「このステージの範囲だけ」とプロンプトで制限し直す（AGENTS.md の確認） |
| `streamlit` が見つからない | 仮想環境の有効化を確認（`codex/Codex開発プロンプト集.md` ステージ0の不具合例） |
| 生成された不具合が、プロンプト集の想定と違う | 想定どおりでなくてよい。**「症状・再現手順・期待する動作」で伝える** 練習をさせる |

## 4. 想定トラブルと対応

| トラブル | 対応 |
|---|---|
| Copilot が応答しない・エラーになる | 再読み込み → 新しいチャット → ブラウザの再起動。解決しなければ講師画面で共有し、解答例で先に進む |
| 利用上限に達した | 講師画面で実演し、受講者は解答例を使って確認・修正の作業に集中する |
| Excel で Copilot ボタンが押せない | OneDrive 保存・自動保存オン・テーブル化を確認 |
| Word でファイルを参照できない | 参照したいファイルが OneDrive に保存されているか確認。だめなら内容をコピーして貼り付け（**判定を確認してから**） |
| 出力が英語になる | 「日本語で回答してください」を追加。プロンプト冒頭に日本語で役割を書く |
| 受講者が実際の顧客情報を入力しそうになった | その場で止め、第3章のルールを確認する。入力してしまった場合は、会社のルールに従って報告するよう伝える |
| 進度に差が出た | 早い人には各演習の「発展」、遅い人には解答例を渡して「確認・修正」だけに集中させる |
