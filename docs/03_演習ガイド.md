# 演習ガイド

## 演習の共通ルール

- 演習素材は `materials/` フォルダにあります。**素材は直接編集せず、コピーして自分の OneDrive に保存** してから使ってください
- ファイル名の先頭に自分の名前を付けます（例：`山田_演習6_議事録.docx`）
- プロンプト例は **そのまま使っても、自分の言葉に変えても構いません**。結果が期待と違ったら、追加の指示で直してみましょう
- 各演習の最後にある **セキュリティチェック** を必ず確認してください
- Copilot の出力は毎回変わります。解答例（`materials/解答例/`）は「一つの完成イメージ」です

## 演習1 基本操作ツアー（第2章・15分）

**ねらい**：Copilot アプリの基本操作に慣れる

**手順**

1. Microsoft Edge で Copilot を開き、Microsoft 365 Premium のアカウントでサインインしていることを確認する
2. 新しいチャットを開き、次のプロンプトを入力する

```
法人向けの研修会社の営業担当者が、初めて訪問する顧客との商談で気をつけるべきことを5つ教えてください。
```

3. 回答の下にある操作で **再生成** し、1回目との違いを確認する
4. 続けて次のように入力し、会話で結果を直せることを確認する

```
今の5つを、新人営業向けに1つ30字以内で言い直してください。
```

5. 応答モードを「じっくり考える」モードに切り替えて、同じ質問をしてみる（画面に表示される名称を確認）
6. 設定画面を開き、**プライバシー（会話データの扱い）に関する設定項目** がどこにあるか確認する（第3章で使います）
7. 新しいチャットを開き、前の会話の内容が引き継がれていないことを確認する

**確認ポイント**
- [ ] 同じ質問でも回答が変わることを確認した
- [ ] 追加の指示で回答を直せた
- [ ] プライバシー設定の場所を確認した

## 演習2 プロンプト改善ドリル（第2章・20分）

**ねらい**：4要素（役割・目的・前提・出力形式）で結果が変わることを体感する

**手順**

1. 次の「悪いプロンプト」を入力し、結果を見る

```
研修のメールを書いて
```

2. 4要素を補って書き直す。次の空欄を埋めて入力する

```
あなたは【役割】です。
【目的】のために、【何を】作成してください。
前提：【相手・状況・条件】
出力形式：【形式・分量】
```

3. 2つの結果を比べ、良くなった点を3つ書き出す
4. **発展**：次のプロンプトで、Copilot 自身にプロンプトを改善させる

```
次のプロンプトを、より良い結果が得られるように改善してください。
改善したプロンプトと、改善した理由を示してください。
プロンプト：「研修のメールを書いて」
```

**確認ポイント**
- [ ] 4要素を含むプロンプトを書けた
- [ ] 結果の違いを具体的に説明できる

## 演習3 顧客・業界の事前調査（第2章・20分）

**ねらい**：Web 検索つきの調査と、出典の確認を体験する

**使う素材**：`01_顧客プロフィール.docx`（読むだけ。Copilot には貼り付けない）

**シナリオ**：みらい商事は架空の会社なので、Web で調べても情報は出てきません。
そこで、**企業の営業部門での生成AI活用の動向と課題** について調べ、ヒアリングの仮説を作ります。

**手順**

1. 顧客プロフィールを読み、顧客の状況（全社約300名、Microsoft 365 利用、Copilot 試行中、利用状況に差がある）を把握する
2. Copilot アプリで次のように依頼する（Web 検索をオンにする）

```
日本企業の法人営業部門で、生成AI（Microsoft Copilot など）を業務に導入する際に
最近話題になっている課題を3つ教えてください。
それぞれに根拠となる出典（公的機関の資料、調査レポート、報道）を付けてください。
```

3. 出典リンクを **少なくとも2つ開き**、回答の内容が本当に書かれているかを確認する
4. 確認できた内容をもとに、次のように仮説を作らせる

```
上の調査結果を踏まえて、従業員300名規模の商社の人材開発担当者が
「生成AIの利用状況に部署や担当者で差がある」という理由で研修を検討している背景として考えられる仮説を3つ挙げてください。
この会社では Microsoft 365 を全社で使い、一部の部署で Copilot を試行しています。
それぞれ、ヒアリングで確かめるための質問を1つずつ付けてください。
```

**確認ポイント**
- [ ] 出典を開いて内容を確認した（確認できなかった情報はメモに「未確認」と書く）
- [ ] 手元の商談メモや顧客プロフィールを Copilot に貼り付けていない

**セキュリティチェック**：調べたのは公開情報だけか？（判定 A の情報のみ）

## 演習4 入力OK/NG判定とマスキング（第3章・17分）

**ねらい**：入力してよい情報を判定し、マスキングして安全に使う

**使う素材**：`02_マスキング演習素材.docx`（初回訪問の前に書いた営業メモ）

**手順**

1. 素材の①〜⑩を読み、**A（入力可）／B（加工すれば可）／C（入力不可）** を判定して表に記入する（Copilot は使わない。自分で考える）

| No | 判定 | 理由・加工方法 |
|---|---|---|
| ① | | |
| … | | |

2. 講師の解説を聞き、判定を確認する
3. 判定に基づいて、Copilot に入力する **加工済みメモ** を作る（C を削除し、B を加工する）
4. 加工済みメモを使って、次のように依頼する

```
次のメモは、法人向け研修会社の営業が初回訪問の前に書いたものです（社名は伏せています）。
初回ヒアリングで確認すべき質問を、「背景」「対象者・対象業務」「内容」「条件（時期・予算・手配）」「進め方（決裁・受講後の支援）」の
5つの分類で、各2〜3問、表形式で作ってください。

メモ：
（ここに加工済みのメモを貼り付ける）
```

**解答（講師の解説後に確認）**

| No | 判定 | 理由・加工方法 |
|---|---|---|
| ① | A | 会社ホームページで公開されている情報 |
| ② | A | 採用ページ等で公開されている情報 |
| ③ | C | 個人の連絡先。目的に不要なので削除する |
| ④ | C | 顧客の未公開情報（組織再編の予定）。秘密保持の対象 |
| ⑤ | C | 特定個人の評価情報。特に慎重に扱うべき個人情報 |
| ⑥ | B | 「競合は中程度の価格帯で提案」と一般化する（社名・金額を伏せる） |
| ⑦ | C | 自社の社外秘の価格方針 |
| ⑧ | B | 社名を伏せ「商社A社」として条件（20名・11月上旬・予算目安）だけを使う |
| ⑨ | C | 認証情報。絶対に入力しない（そもそもメモに書かない） |
| ⑩ | A | 一般的な動向 |

> **補足**：①② は公開情報ですが、①②と⑧を組み合わせると会社が特定できます。
> 本研修の環境（個人向けプラン）では、**社名を伏せて使う** のを基本にします。

**確認ポイント**
- [ ] C の情報をすべて取り除いた
- [ ] B の情報を加工した
- [ ] 加工済みメモから顧客が特定できないか、もう一度確認した

## 演習5 ヒアリングシートの作成（第4章・30分）

**ねらい**：Word の Copilot で、白紙から実務で使える文書を作る

**使う素材**：演習3の仮説、演習4の質問案

**手順**

1. Word で新規文書を作り、OneDrive に `（名前）_演習5_ヒアリングシート.docx` として保存する
2. Copilot で下書きを依頼する

```
法人向け研修会社の営業が、初回訪問（オンライン会議・60分）で使うヒアリングシートを作ってください。
顧客は商社の人材開発担当者と営業企画担当者で、社内の生成AIの利用状況に差があることを課題として、
法人営業の担当者向けの研修を検討しています。Microsoft 365 を全社で使い、一部の部署で Copilot を試行中です。

構成：
1. 訪問の目的（冒頭で伝える一言）
2. ヒアリング項目の表（分類／質問／聞き取り欄／重要度）
3. こちらから伝えること（研修の組み立て、進め方）
4. 次回アクションの確認欄

分類は「背景」「対象者・対象業務」「内容」「条件（時期・予算・手配）」「進め方（決裁・受講後の支援）」とし、
重要度は ◎○△ で示してください。
```

3. 生成された表の質問に、演習3・4で考えた質問が入っているか確認し、足りなければ追加を依頼する

```
次の質問を追加してください。
・対象者全員が、研修で使う Copilot の機能を利用できる状態か（ライセンスの割り当て範囲）
・予算は承認済みか、最終的に誰が承認するか
・受講後の活用支援を社内でどなたが担当できるか
```

4. 質問を1つ選択し、Copilot の **書き換え** で表現を柔らかくする（承認者を聞く質問がおすすめ）
5. 体裁を整えて保存する

**確認ポイント**
- [ ] 60分で聞ききれる分量になっているか（多すぎる場合は重要度 ◎ に絞る指示を出す）
- [ ] ライセンス・予算承認・受講後の支援担当など、**後で困る前提** を確認する質問が入っているか

> **答え合わせ**：実際の商談（演習6の文字起こし）では、これらの質問のうち多くが「未確認」という答えでした。
> 事前に聞く準備をしておくと、「決まっていないこと」を早く見つけられます。

## 演習6 商談議事録の作成（第4章・35分）

**ねらい**：自動文字起こしから、決定事項と未確定事項を区別した正確な議事録を作る

**使う素材**：`03_商談文字起こし_初回訪問.docx`（2026年10月6日（火）の Zoom での初回訪問。話者は「話者A／B／C」で記録）

**手順**

1. 素材をコピーし、`（名前）_演習6_議事録.docx` として OneDrive に保存する
2. **話者を特定する**：冒頭の自己紹介から、話者A＝ELI 高橋、話者B＝佐藤様（人材開発担当）、話者C＝田中様（営業企画担当）であることを確認する
3. **セキュリティ前処理**：Word の置換機能（Ctrl＋H）で、社名・氏名を記号に置き換える。**長い語から** 置き換える（先に「佐藤」を置き換えると「顧客担当者B美和」のように名前の一部が残るため）
   - 「みらい商事」→「A社」、「佐藤美和」「佐藤」→「顧客担当者B」、「田中淳」「田中」→「顧客担当者C」
4. Copilot ウィンドウで、まず内容を把握する

```
この文字起こしの内容を3行で要約してください。話者Aは研修会社の営業、話者Bと話者Cは顧客の担当者です。
```

5. 議事録を依頼する（Copilot の下書き機能で新規文書に作らせてもよい）

```
この文字起こしをもとに、社内共有用の商談議事録を作成してください。
話者Aは研修会社の営業（当社）、話者Bは顧客の人材開発担当、話者Cは顧客の営業企画担当です。

構成：
1. 会議の概要（日時・方法・出席者）
2. 背景
3. 確認した内容（対象・対象業務・内容・手配・提案2案の金額と内訳・予算・決裁・効果の確認・時期）を表で
4. 決定事項
5. 未確定事項（確認事項）：内容／現在の状況／担当・期限
6. Next Action（担当・内容・期限の表）

条件：
- 会議日は2026年10月6日（火）です。「今週金曜」「来週月曜」「来週火曜」などの相対的な日付は、具体的な日付と曜日に直してください
- 明確に合意されたことだけを決定事項にしてください
- 決まっていないことは未確定事項に入れ、担当や期限が決まっていなければ「未定」と書いてください。推測で補わないでください
- 「案として出す」と言ったもの（事前アンケート）は、合意事項にしないでください
- 雑談や、業務に関係しない話は除いてください
```

6. 出力を **文字起こしと照合** し、次の点を確認・修正する
   - 金額：A案 60万円（1名3万円）、B案 100万円（1名5万円）、差額40万円 ＝ 事前診断20万円＋活用フォロー20万円（税抜）
   - 予算：100万円は **目安** で、承認済みの上限ではない。最終的な承認者は金額確定後に確認
   - 期限：10/9（金）骨子送付、10/12（月）田中様、10/13（火）佐藤様、10/16（金）14:00 提案
   - 未確定事項：Copilot の利用可否（担当・期限も未定）、A案の場合のフォロー担当、予算承認、実施日・会場
7. 記号（A社・顧客担当者B など）を元の名前に戻し、解答例 `解答例_演習6_商談議事録.docx` と比べる

**確認ポイント**
- [ ] 相対的な日付が具体的な日付になっている
- [ ] 未確定事項に、推測の担当・期限が入っていない
- [ ] 事前アンケートが「合意事項」になっていない
- [ ] 効果の確認方法（直後・2週間後・1か月後の3段階、削減時間を金額に換算しない）が入っている

**セキュリティチェック**：Copilot に渡す前に、社名・氏名を置き換えたか？

## 演習7 議事録と Next Action の送付メール（第5章・20分）

**ねらい**：同じ情報を、相手に合わせた文面に変換する

**使う素材**：演習6の議事録

**手順**

1. 議事録を開いた状態で、Copilot に依頼する（Outlook を使える場合は Outlook の Copilot でもよい）

```
この議事録を顧客に送るためのメールを作成してください。
宛先は顧客の人材開発担当の佐藤様、CC は営業企画担当の田中様です。差出人は高橋です。

条件：
- 本日の打ち合わせへのお礼
- 議事録と Next Action を送付する旨
- 確認した内容の要点（3点程度）
- Next Action（双方の担当と期限）
- 確認事項（未確定のもの）を、未確定であることが分かるように書く
- 推測で担当や期限を補わない。事前アンケートは合意事項として書かない
- ビジネスメールとして標準的な丁寧さで、500字程度
```

2. 次の観点で確認し、必要なら追加の指示で直す
   - 敬称・社名は正しいか（「みらい商事株式会社」— 株式会社は後ろ）
   - 金額・日付・曜日が議事録と一致しているか
   - 長すぎないか（「もう少し短く」「箇条書きを減らして」）
3. 完成したメールを Word に貼り付けて保存する（研修では **実際には送信しない**）

**確認ポイント**
- [ ] 未確定事項を確定したように書いていない
- [ ] 日付と曜日が正しい

## 演習8 上長への商談報告・行動リスト・確認事項の一覧（第5章・25分）

**ねらい**：社内向けの簡潔な報告と、抜け漏れのない行動リスト、顧客に渡す確認事項の一覧を作る

**手順**

1. 議事録をもとに、自社の上長への報告を依頼する

```
この議事録をもとに、自社の上長への商談報告をチャット用に作成してください。
次の型で、全体で300字以内にしてください。
【結論】受注確度（A/B/C）と次のマイルストーン
【ポイント】ニーズ／決め手／リスク（各1行）
【ご相談】上長に相談したいこと
【次の一手】日付つきの予定
```

2. 「受注確度」の判断は Copilot に任せず、**自分で決めて** 修正する（判断の理由も考える）
   - ヒント：予算は目安で承認前、最終承認者は未確認、Copilot の利用可否も未確認 — これをどう評価するか
3. 自分の行動リストを作る

```
この議事録から、当社（高橋）が行うべきことと、顧客側の対応のうち当社がフォローすべきことを抜き出し、
「No／アクション／担当／期限／状態」の表にしてください。
期限は具体的な日付と曜日で書き、状態はすべて「未着手」または「待ち」にしてください。
提案（10月16日14時）の準備は、前日までに終わるように期限を提案してください。
```

4. **確認事項の一覧** を作る（10/16 の提案に添付するもの）

```
この議事録から、未確定の事項だけを抜き出し、「確認事項／現在の状況／担当／期限」の表にしてください。
担当や期限が決まっていないものは「未定」と書き、推測で補わないでください。
```

5. 表を確認し、商談で「確認事項」として挙げた3点（Copilot の利用可否、フォローの担当、予算承認の状況）が入っているか確認する

**確認ポイント**
- [ ] 報告は結論から書かれている
- [ ] 行動リストに担当と期限がすべて入っている
- [ ] 確認事項の一覧で、未定のものが「未定」のままになっている

> **気付き**：演習6〜8では、同じ情報を何度もプロンプトに書き、同じ確認を繰り返しました。

## 演習9 研修実績データの分析（第6章・40分）

**ねらい**：Excel の Copilot で分析し、B案の追加支援（事前診断・活用フォロー）を説明する材料を見つける

**使う素材**：`04_研修実績データ.xlsx`（当社の2023〜2025年度の架空の実績160件）

**手順**

1. 素材をコピーして OneDrive に保存し、Excel で開く（データはテーブルになっています）
2. **データの品質を確認する**

```
このデータで、分析の前に直したほうがよい点（表記のゆれ、空欄など）はありますか？
```

   → 「顧客業種」の **「卸売」「情報通信」という表記ゆれ** と、**満足度の空欄（1件）** が見つかるはず。
   表記ゆれを「卸売業」「情報通信業」に直す（置換機能か、Copilot に依頼）
