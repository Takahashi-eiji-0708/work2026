# AGENTS.md — ELI Sales Assist 開発ルール

このファイルは、コーディングエージェント（Codex）がこのリポジトリで作業するときのルールです。

## 作るもの

法人営業の担当者が、商談後の作業（議事録・メール下書き・行動管理）を行うための Web アプリ。
研修用のサンプルで、利用者は数名。架空のデータだけを扱う。

## 技術

- Python 3.11 以上
- 画面：Streamlit（`app.py`）
- データ保存：SQLite（標準ライブラリの `sqlite3`）。保存先は環境変数 `DB_PATH`
- LLM：`LLM_PROVIDER` が `mock` のときは API キーなしで動くモック、`openai` のときは OpenAI API
- テスト：pytest（`tests/`）
- 処理は `sales_assist/` パッケージにまとめ、`app.py` は画面の組み立てだけにする

## 必ず守ること

1. **API キーをコードに書かない**。`.env`（`.gitignore` 済み）か環境変数から読む。`.env.example` には値を入れない
2. **商談メモの本文をログや例外メッセージに出さない**。ログに出してよいのは ID・文字数・件数だけ
3. **AI に送る前に必ずマスキングする**（電話番号・メールアドレス・登録した語句）。置換表は AI に送らない
4. AI の出力は **JSON として検証** してから使う。形式が違う場合は1回だけ再試行し、だめなら画面に分かりやすいエラーを出す
5. 画面の文言はすべて日本語にする
6. 新しいライブラリを追加するときは、理由を説明して `requirements.txt` に追記する
7. 1回の作業では **指示されたステージの範囲だけ** を変更する。関係ないファイルを書き換えない

## 作業の進め方

- 変更後は `python -m pytest -q` を実行し、すべて成功することを確認する
- 不具合を直したときは、**その不具合を再現するテストを先に追加** してから修正する
- 作業の最後に、変更したファイルと、利用者が画面で確認すべき手順を日本語で箇条書きにする
