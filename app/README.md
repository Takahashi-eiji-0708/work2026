# ELI Sales Assist（研修用サンプルアプリ・参照実装）

商談後の3つの作業 —— **議事録・メール下書き・行動管理** —— を1つの画面で支援するサンプルアプリです。
研修の第9章（デモ）と第10章（開発トラックの完成形）で使います。

> 研修用のサンプルです。業務で使う場合は、会社の承認、法人契約の API、セキュリティ審査が必要です。
> 画面には **架空のデータだけ** を入力してください。

## 機能

| タブ | 内容 |
|---|---|
| 商談登録 | 顧客名・商談日・出席者・商談メモ（文字起こし）を登録（SQLite に保存） |
| 議事録 | AI に送る内容（マスキング済み）を確認 → 議事録を生成。相対的な期限を具体的な日付に変換し、名前を元に戻して表示 |
| メール下書き | 宛先（顧客／社内）とトーンを選んで下書きを作成。送信はしない |
| 行動管理 | 議事録から抽出したアクションを期限順に表示。期限切れの強調、状態の更新、期限の手動設定、CSV 出力（Excel で文字化けしない） |
| マスキング設定 | AI に送る前に置き換える社名・人名を登録。電話番号・メールアドレスは自動で置き換え |

## 起動方法

```bash
cd app
python -m venv .venv
# Windows: .venv\Scripts\activate ／ macOS・Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
streamlit run app.py
```

ブラウザで http://localhost:8501 が開きます。

- 既定は **モックモード**（`LLM_PROVIDER=mock`）で、API キーなしで動きます。モックはキーワードで簡易的に議事録を組み立てるため、文章の質は実際の LLM より劣ります
- OpenAI API を使う場合は `.env` に `LLM_PROVIDER=openai` と `OPENAI_API_KEY` を設定します。`OPENAI_MODEL` は利用できるモデル名に変更してください
- API キーが未設定の場合は、エラーにせずモックモードで起動し、画面に警告を表示します

## 構成

```
app/
├── app.py                  画面（Streamlit）
├── sales_assist/
│   ├── config.py           設定の読み込み（.env / 環境変数）。API キー未設定時はモックに切り替え
│   ├── db.py               SQLite（商談・議事録・アクション・マスキング語句）
│   ├── masking.py          マスキングと復元（全角・ハイフン違いの電話番号にも対応）
│   ├── dates.py            「来週金曜」などの期限表現 → 具体的な日付
│   ├── prompts.py          プロンプトテンプレート（出力は JSON 形式に固定）
│   ├── llm.py              LLM の呼び出し（mock / openai）と JSON の取り出し
│   └── services.py         マスキング → LLM → 検証 → 日付変換 → 復元 の一連の処理、CSV 出力
├── tests/test_core.py      各ステージで直した不具合の再発防止テスト
├── AGENTS.md               Codex に渡す開発ルール
└── .env.example            設定の見本（.env はリポジトリに含めない）
```

## セキュリティ上の工夫

- AI に送る前に、電話番号・メールアドレス・登録した社名・人名を置き換える。置換表は AI に送らない
- 送信内容を画面で確認し、チェックを入れないと生成ボタンが押せない
- API キーは `.env`（`.gitignore` 済み）または環境変数から読む。コードに書かない
- ログには商談の本文を出さない（文字数・置換件数などのメタ情報のみ）
- メールは下書きまで。送信はしない
- 制約：マスキングは登録した語句と決まったパターンにしか効かない。**最後は人が確認する**
